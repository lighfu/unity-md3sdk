UnityAgent 文字「歯抜け」バグ — 根本対策

案 A: FontAsset ディスク永続化 2026-05-22 対象: unity-md3sdk + unity-agent 状態: 承認済み (2026-05-22)

1背景 — 根本原因

UnityAgent のチャット画面で、文字の一部が透明化して「歯抜け」になり、 別の文字（"ち" など）が混入する。これは文字列処理のバグではなく、 UI Toolkit の動的 FontAsset の内部アトラステクスチャがドメインリロードで破棄されるグリフ描画バグ。

  • チャット UI は UI Toolkit の Label。フォントは FontAsset.CreateFontAsset() による実行時生成の動的 FontAsset。
  • ドメインリロード（スクリプト再コンパイル）/ プレイモード遷移 / AssetDatabase.Refresh で、FontAsset の C# オブジェクトは生存するが、内部の atlasTextures（Texture2D）だけが破棄される。
  • Label がこの半壊 FontAsset を参照し続け、グリフが透明（=歯抜け、レイアウト幅は残る）または別アトラスセル誤参照で別文字混入。
  • UnityAgent はツール実行でプロジェクトを書き換え → 再コンパイル → ストリーミング中にドメインリロード、が「たまに」起きる主因。
既存の対症療法（調査で確認済み）: unity-md3sdk 側に IsFontAssetBroken / ScheduleRefreshRetry / RefreshAllWindows / MD3FontAutoSetup が多数。 さらに unity-agent 側の UnityAgentWindow.CreateGUI()（250-257 行）に、 ドメインリロード直後の 歯抜けテキスト＋UIRStylePainter.DrawTextInfo の NullRef クラッシュ を防ぐための ClearFontCache() ＋ RefreshAllWindows() 緩和ブロックが存在。 いずれも delayCall 依存の race window が残り、 ProtectFontAsset の HideAndDontSave もリロードでの破棄は防げない。

2方式案の比較

案内容評価判定
A. FontAsset ディスクアセット化 FontAsset 本体・アトラステクスチャ・マテリアルを .asset として保存。アトラスがディスクアセットになりリロードで破棄されない。 真の根本対策。中程度の複雑さ。生成物が Assets/ に出る。 採用
B. 静的アトラス事前ベイク 必要グリフを全部静的アトラスへ焼く。 CJK は数万グリフ → 巨大アトラス・ディスク肥大・セットアップ激遅。 却下
C. リアクティブ再構築の強化 beforeAssemblyReload 等で先回り再構築。 「描画前に再構築完了」を保証できず race は原理的に消えない。 却下
アトラスの Texture2D が「実行時オブジェクト」である限りリロードで必ず破棄される。 これを「ディスクアセット」にすることだけが race を原理的に消す唯一の方法 → 案 A を採用。

3設計（案 A）

3.1　新コンポーネント MD3FontAssetStore

責務を 1 つに絞った新ユーティリティを追加（unity-md3sdk/MD3FontAssetStore.cs）。

  • GetOrCreate(key, baseFont, fallbackFonts) → ディスク永続化された FontAsset を返す。 既に .asset があればロードして返す（リロード後はこの経路でアトラスが無傷のまま復帰）。 無ければ生成 → AssetDatabase.CreateAsset + AddObjectToAsset（アトラス・マテリアルをサブアセット化）→ 保存。
  • InvalidateAll() → 生成物を削除し再生成を促す。

MD3Theme と MD3Icon の両方がこれを使う。アイコンフォントも同じ根本原因なので一緒に対策。

3.2　データフロー

MD3Theme.LoadFontAsset()
  └→ MD3FontAssetStore.GetOrCreate("theme-<activePrefix>", baseFont, fallbacks)
       ├─ ディスクに .asset あり → LoadAssetAtPath で返す  （リロード耐性あり）
       └─ なし → 生成 → CreateAsset / AddObjectToAsset で保存 → 返す

MD3Icon → GetOrCreate("icon", iconFont) / GetOrCreate("icon-filled", filledFont)
アトラスは保存後も Dynamic のまま。リロード後はディスクの（中身は空でも有効な）テクスチャが復帰し、 グリフはオンデマンドで再ラスタライズされる。 破棄テクスチャ＝歯抜け が 有効な空テクスチャ＝即再描画 に変わるのが肝。

3.3　生成物の配置

Assets/MD3SDKFonts/ ← 既存（DLフォント保存先） ├─ NotoSansJP-Regular.otf ├─ ... └─ Generated/ ← 新規 ├─ MD3_FA_theme-NotoSansJP.asset FontAsset + atlas/material をサブアセット化 ├─ MD3_FA_icon.asset └─ MD3_FA_icon-filled.asset

MD3SDK は読み取り専用 VPM パッケージのため、生成物は既存の DL フォントと同じ Assets/MD3SDKFonts/ 配下に置く（前例踏襲）。

3.4　無効化（フォント設定変更時）

ActiveFontPrefix 変更・フォント DL/削除・Emoji トグル時に InvalidateAll() → 次回 LoadFontAsset で再生成 → RefreshAllWindows()。 これは既存フローと同じで、バグ（＝設定不変のままのリロード）とは別経路。

3.5　既存コードの整理（「整理込み」方針）

対象処置
ScheduleRefreshRetry / s_refreshRetryScheduled維持 — 起動時の AssetDatabase 未準備に備えた 1 ショットの安全網として残す（§3.6 と整合）
MD3FontAutoSetup の race 対策・OnAfterAssemblyReload のキャッシュクリア削除 — ディスクアセットは生き残る
ProtectFontAsset の HideAndDontSave修正 — 永続化と矛盾するため永続 FontAsset には適用しない
IsFontAssetBroken縮小 — null/破棄チェックのみの軽量な安全網として維持（defense-in-depth）
RefreshAllWindows維持 — 設定変更時の再適用用に残す
UnityAgentWindow.CreateGUI() の緩和ブロック（250-257 行）簡素化 — _theme.ApplyTo() のみ残し、ClearFontCache()＋RefreshAllWindows() の歯抜け回避ペアを削除（根本対策で不要に）

3.6　エラー処理

  • 起動直後で AssetDatabase ビジー → 生成失敗時はその場は実行時 CreateFontAsset（現行挙動）にグレースフル縮退し、次 tick で永続化を軽量に 1 回だけ再試行。
  • ソース Font 欠如 → null を返し、呼び出し側が FontDefinition.FromFont にフォールバック。
  • 生成アセットが破損 → 軽量 IsFontAssetBroken が検知 → 削除して再生成。

3.7　検証

歯抜け再現テスト

チャットでメッセージ送信中／後にスクリプト再コンパイルを誘発 → 歯抜けが出ないことを確認。

生成物の確認

Generated/ に .asset ＋ アトラスのサブアセットが生成されることを確認。

フォント変更テスト

設定で Active フォントを変更 → 正しく再生成・描画されることを確認。

Unity Editor のフォント描画はヘッドレステスト不可のため、検証は Unity 上での手動確認となる。
